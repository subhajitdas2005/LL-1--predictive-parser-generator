What is an LL(1) Parser?

An LL(1) parser is a deterministic, top-down predictive parser for Context-Free Grammars. The name stands for:

  • L: Reads input from Left-to-Right.
  • L: Constructs a Leftmost Derivation.
  • (1): Uses 1 token of lookahead to make deterministic parsing decisions without backtracking.

FIRST Set Computation

For any grammar symbol X, FIRST(X) is the set of terminals that can begin strings derived from X:

  • If X is a terminal, FIRST(X) = { X }.
  • If X → ε is a production, ε ∈ FIRST(X).
  • For X → Y1 Y2 ... Yk, add FIRST(Y1) - {ε}. If Y1 ⇒* ε, add FIRST(Y2) - {ε}, cascading until a non-nullable symbol is reached.
  • If all Y1 ... Yk ⇒* ε, then ε ∈ FIRST(X).

FOLLOW Set Computation

For non-terminal A, FOLLOW(A) is the set of terminals that can appear immediately to the right of A in some sentential form:

  • Rule 1: Put $ (input end-marker) into FOLLOW(StartSymbol).
  • Rule 2: For A → α B β, add FIRST(β) - {ε} to FOLLOW(B).
  • Rule 3 & 4: If A → α B or A → α B β where β ⇒* ε, everything in FOLLOW(A) is in FOLLOW(B).

LL(1) Table Construction Rules

For every production A → α:

  • For each terminal a ∈ FIRST(α) - {ε}, add A → α to table entry M[A, a].
  • If ε ∈ FIRST(α), then for each terminal or end-marker b ∈ FOLLOW(A), add A → α to M[A, b].
  • Any cell containing 2 or more distinct productions indicates an LL(1) Conflict.

LL(1) Conflicts & Decidability

Two primary types of LL(1) non-deterministic conflicts can occur:

  • FIRST/FIRST Conflict: Two alternatives of A derive words starting with the same terminal (e.g. A → a B | a C). Resolved via Left Factoring.
  • FIRST/FOLLOW Conflict: Occurs when ε ∈ FIRST(α) and FIRST(α) ∩ FOLLOW(A) ≠ ∅. Often caused by ambiguous constructs like the dangling else.
  • CFG Ambiguity Decidability: Detecting whether an arbitrary CFG is ambiguous is undecidable (proven via Post Correspondence Problem). LL(1) conflict detection checks the specific decidable condition for predictive parsing.

Direct Left Recursion Elimination

Direct left recursion occurs when A → A α | β. A predictive parser would loop infinitely trying to expand A.

Standard transformation replaces:

A → β A'
A' → α A' | ε

This generator detects left recursion and provides one-click automatic elimination.
